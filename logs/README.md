# 개발 로그 정책

검사·빌드는 기본적으로 터미널에 출력합니다. 성공할 때마다 파일을 남길 필요가 없습니다. 현재 npm 검사 명령도 파일을 자동 생성하지 않습니다.

실패를 조사할 때만 `logs/latest-failure.log` 같은 고정 파일을 덮어쓰고 조사 후 정리합니다. 날짜·재시도별 파일이나 별도 완료 MD를 만들지 않습니다. Git에 로그 내용을 올리지 않습니다.

| 명령 | 동작 |
|---|---|
| `npm run logs:check` | 루트의 개발 `.log`·`.log.N` 파일이 있으면 실패. 파일을 이동하거나 삭제하지 않음. `check:encoding`에서도 먼저 실행 |
| `npm run logs:collect` | 루트 개발 로그를 logs/로 이동. 같은 이름은 최신 파일만 남기고 번호 사본을 만들지 않음. 이동 후 보관 상한 적용 |
| `npm run logs:clean` | 최대 14일·최근 20개·합계 10MiB 범위만 보관 |
| `npm run logs:clean -- --all` | 루트와 logs/ 아래 개발 `.log` 및 `.log.N` 파일 전부 정리 |
| `npm run logs:clean -- --dry-run` | 삭제 없이 정리 대상 건수·용량 확인 |

기한·개수·용량 중 하나라도 넘으면 오래된 개발 로그부터 정리합니다. 열려 있는 파일은 실패를 알리고 남겨 두며 작업공간 밖·심볼릭 링크·node_modules·.git·백업은 따라가지 않습니다.

로그 파일이 꼭 필요하면 처음부터 `logs/` 아래의 고정 경로로 지정합니다. 루트의 `> build.log`, `Tee-Object build.log` 같은 출력은 사용하지 않습니다. `logs:check`는 터미널의 임의 리디렉션을 막는 기능이 아니라, 루트에 남긴 로그를 검증 단계에서 발견하는 검사입니다. 기존 파일을 모두 이동·보존하라는 요청에서는 보관 정리를 함께 실행하지 않습니다.

**삭제하지 않는 것:** DB 감사/원장, migration 영수증, Railway 운영 로그, JSON 검토 자료, 원본, 백업, 이 폴더의 README와 조사 스크립트. 확인하지 않은 조사 자료를 개발 로그로 간주하지 않습니다.
