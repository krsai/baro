# 공통 UI 사용 기준

일반 조회 표는 `tableLayout.js`의 공통 규칙으로 PC 작업 영역에 먼저 맞춘다. 불필요한 최소 너비·고정 열 너비를 풀고 가로 여백과 텍스트 줄바꿈으로 조정하며, 글자나 금액을 축소·생략하지 않는다. 마지막 작업 열의 직접 버튼·버튼 그룹·`DeleteActionButton`은 스크롤 중에도 우측에 남는다. 별도 작업 셀은 `data-table-actions`로 표시한다.

우측 고정 작업 열의 왼쪽에 구분용 세로선이나 그림자를 표시하지 않는다. 고정 위치·배경·행 호버와 삭제 보호 조건은 유지한다.

스크롤 고정 머리글은 본문 작업 버튼보다 위에 표시하며, 우측 고정 열과 교차하는 머리글은 다른 머리글보다 위에 둔다. 공통 검색창의 ‘선택’ 제목도 상하·좌우 스크롤 중 가려지지 않아야 한다. 표의 작업 열 판별 CSS에는 중첩 `:has()`를 사용하지 않는다.

모달과 임시 Drawer에는 닫기 용도의 취소 버튼을 두지 않는다. 바깥 클릭과 Esc는 기존 onClose 및 미저장 확인을 사용하고 저장 중·결과 미확인 상태의 닫기 제한은 유지한다. 저장·확인·선택과 휴가/출고/실적 등록 자체를 취소하는 업무 동작은 구별한다. 취소만 있던 빈 DialogActions는 제거한다.

업무상 열 너비가 필요한 날짜·사이즈·급여 매트릭스는 `data-table-layout="wide"`, 인쇄 문서는 `document`로 명시한다. 고정 비율 요약표는 `fixed`, 유연한 표 안에서 열 설정을 유지하려면 `columns`를 사용한다. 편집 입력이 있는 표는 기존 입력 너비를 유지하고, 공간이 부족하면 표 내부에서 스크롤한다.

- 일반 색상·모서리·표 간격: `ui.js`
- 라벨의 배경·글자·테두리 색상: `labelPalette.js`
- 표·입력창·버튼·Chip의 기본 표시: `index.js`의 MUI 테마
- 화면 배치와 조회 도구: `AppPageContainer`, `PageToolbar`

본문·표·일반 컨트롤의 기본 글자 크기는 13px이며 `ui.typography`, `ui.table`, `ui.control`이 같은 기준을 공유한다. 제목·합계·보조 설명은 각각 별도 의미 토큰을 사용한다. HTML 화면도 `--ui-body-font-size`, `--ui-control-font-size`, `--ui-table-font-size`를 사용한다. CSS 초기화 선택자의 우선순위는 낮춰 MUI나 역할별 토큰을 덮어쓰지 않는다.

페이지별 배치·강조·밀도 조정은 허용한다. 공통 역할의 기본 디자인은 테마/컴포넌트에 먼저 정의하고, 화면에서 필요한 차이만 조정한다. 직접 지정한 값이 있다는 이유만으로 모두 제거하지 않는다.

모달 제목·본문·하단 버튼 영역의 기본 여백은 `ui.dialog`와 전역 `MuiDialogTitle/Content/Actions`에서 관리한다. 저장 동작은 `SaveButton`을 재사용하며 기본 모서리는 일반 버튼과 같다. 화면별 열 구성·넓이·스크롤·특수 작업은 호출부에서 조정할 수 있다.

아이콘형 행 삭제는 `DeleteActionButton`을 사용한다. 활성 상태는 빨강, 비활성은 회색, 호버는 옅은 빨강 배경으로 표시한다. 화면의 삭제 조건·확인창·이벤트 전파는 호출부에서 유지하며 `disabled`, `title`, `aria-label`, `stopPropagation`을 전달한다. 텍스트가 있는 문서 전체 삭제 버튼과 대화상자 닫기 버튼은 별도 역할을 유지한다.

아이콘형 행 추가는 `AddActionButton`의 파란색 `+`를 사용한다. `DeleteActionButton`과 같은 공통 아이콘 크기·상태·접근성 규약을 사용하며 화면별 아이콘·색·패딩을 복제하지 않는다. 추가 위치·행 수 제한·잠금·이벤트 전파는 호출부에서 유지한다. 비용·지급 회차·청구 항목·입출금·작업 기록의 행 추가는 이 컴포넌트를 재사용한다. 새 문서 생성과 추가 항목 메뉴는 행 추가와 구별한다.

일반 컨트롤은 `ui.control`을 단일 크기 기준으로 사용한다. 텍스트·숫자·검색 선택·드롭다운·날짜·월 입력과 버튼은 기본 높이 36px, 글자 13px, 줄 높이 20px다. 아이콘 버튼은 작은 크기 28px·기본 36px·큰 크기 40px를 사용한다. M+/M−는 각 17px와 간격 2px로 전체 36px를 맞춘다. 여러 줄 입력과 복수 선택은 최소 높이에서 내용에 따라 늘어난다. 화면별 높이·폰트 강제 지정 대신 공통 토큰과 테마를 수정한다. HTML 컨트롤도 전역 `--ui-control-*` 변수를 재사용한다.

라벨 색상은 페이지에 HEX로 복사하지 않는다. 기존 `<Chip color="success" />`도 전역 파스텔 톤을 적용받는다. `outlined`는 동일한 배경에 옅은 테두리를 추가한다. 클릭·삭제·비활성 동작은 MUI Chip을 그대로 사용한다.

공통 검색 선택 `LookupInput`의 라벨은 빈 값·비활성 상태에서도 상단에 고정한다. 돋보기는 줄어들지 않는 별도 끝 영역과 공통 작은 아이콘 크기를 사용하고 입력 글자만 남은 너비를 쓴다. 돋보기 공간에 입력 안쪽 여백을 중복 적용하거나 라벨을 겹쳐 놓지 않는다. 칩을 입력 안에 표시하는 복수 선택의 줄바꿈·최소 입력 너비와 기존 키보드 확정 규약은 유지한다. 화면별 절대 위치나 임시 여백으로 돋보기 겹침을 보정하지 않는다.

회계 입력은 대상 → 회계 코드/내역 → 금액 → 지급 조건/증빙 → 행 작업 순서로 배치한다. 청구 대상·지급 대상은 코드와 읽기 전용 이름, 검색 목록과 우측 상세의 공통 구성을 쓴다. 입출금의 회사 계좌는 각 행 From/To에 포함하며 별도 상단 선택과 중복시키지 않는다. 날짜·통화·문서 유형 등 공통 조건과 주문 청구의 원본 산출 조건은 문서 헤더에 둘 수 있다.

공통 검색 선택은 Enter/Tab에서 코드·전체 이름이 정확히 일치하는 유일한 항목만 바로 확정한다. 부분 입력은 후보가 하나뿐이어도 입력한 검색어를 유지한 모달을 열어 직접 선택한다. 화면별로 유일한 부분 일치를 자동 확정하는 예외를 추가하지 않는다. blur 정확 일치·IME·Shift+Tab·선택 후 포커스 복귀는 유지한다.

새 상태 표시는 공통 컴포넌트를 사용한다.

회계 목록의 여러 코드는 첫 코드와 `외 N건`으로 요약하며 항목 수는 중복 코드의 별도 행도 포함한다. 비용 수정은 지급 방식/회차와 증빙·참조를 모달로 옮겨 한 줄을 유지한다. 축약한 단위·내역은 title로 전체 내용을 제공한다. 명명된 회사 계좌의 확정 값은 계좌명만 표시하고 선택창에서는 계좌번호·통화로 구분한다. 입출금의 연결 비용은 코드·금액별 행으로 표시하되 실제 은행 거래를 중복 집계하지 않는다.

```jsx
<StatusLabel label={translatedLabel} tone="blue" />
<StatusLabel label={translatedLabel} tone="green" dot />
```

| 의미 | tone | MUI color |
| --- | --- | --- |
| 진행·정보 | blue | primary / info |
| 정상·완료 | green | success |
| 주의·검토 | yellow | warning |
| 오류·지연 | red | error |
| 중립·준비 | gray | default |
| 별도 분류 | purple | secondary |

기존 급여 유형 등의 분류에는 `orange` 등 기존 명명 팔레트를 유지한다. 상태 키와 톤의 연결은 해당 도메인에서 명시한다. 번역 문구나 진행률로 상태를 추측하지 않는다. 점은 색상을 보완하는 장식이며 상태 문구를 함께 표시한다.

MUI가 아닌 배경·막대에도 `LABEL_PALETTE` 또는 `getLabelPalette()`를 재사용한다. 출력 문서의 불변 스냅샷과 인쇄 전용 색상은 별도 계약을 따른다.

비용 신청처럼 HTML/CSS로 작성된 화면은 `CssBaseline`이 내보내는 `--color-*`, `--ui-*`, `--label-{tone}-{background|text|border}` 변수를 사용한다. 브라우저 검증도 실제 앱처럼 공통 ThemeProvider와 CssBaseline을 포함해야 한다. 표의 열·필터·선택·조회 정책은 유지하며, 비용 내역의 구분을 결재 상태로 바꾸어 표시하지 않는다.

날짜·월 선택기의 색상은 전역 MUI X 테마에서 관리한다. 입력·팝업은 공통 표면·테두리 색상, 선택일·선택월·선택연도는 파랑 라벨 팔레트, 요일과 이동 아이콘은 공통 보조 글자색을 사용한다. 톤 변경을 위해 선택기의 크기·배치·포맷·날짜 제한·월 이동 동작을 페이지별로 바꾸지 않는다.


조회·대상 기간은 공통 `DateRangeSelector`를 사용한다. 시작일·종료일과 월 이동 컨트롤을 함께 제공하며 콜백은 dayjs 값을 받는다. 임의 날짜 범위를 페이지에서 다시 월초·월말로 반올림하지 않는다. 월별 급여·정산 문서는 `periodMonthKeys`로 겹치는 월을 선택하고 기존 월별 계산·잠금·스냅샷을 보존한다. 버전 적용 시작월은 별도 업무 값이다.

Dialog의 크기·내부 스크롤은 공통 테마가, 업무 Drawer의 작업 영역 내 여백·위치는 `WorkspaceDialogScope`가 관리한다. 페이지별 고정 헤더 높이를 Drawer top에 더하지 않는다.
- 작업 영역의 선택창·모달은 닫기 전 원래 입력/버튼을 기억하고, 닫힌 뒤 원래 폼의 inert·접근성 숨김이 해제되면 포커스를 복귀시킨다. 중첩 모달도 바로 이전 입력으로 복귀한다. 비활성 탭·제거된/비활성 입력으로 복귀하거나 사용자가 다른 곳으로 옮긴 포커스를 빼앗지 않는다. 선택 확정 뒤 Tab·Shift+Tab은 복귀한 입력을 기준으로 이동한다.
- 모달 제목·본문·버튼 사이에는 기본 구분선을 넣지 않는다. `dividers`를 사용한 기존 모달도 동일하다. 영역은 공통 `ui.dialog` 여백으로 구분하고 입력란·표·상태 카드 자체의 의미 있는 테두리는 유지한다. 제목 바로 아래 본문의 상단 여백은 최소 16px이며 제목·본문·버튼의 좌우 기준선을 맞춘다.

취소가 최종 확정된 목록·이력 행은 `data-cancelled={true}`로 표시한다. 공통 테마가 날짜·대상·내역·금액과 중첩 텍스트에 취소선을 적용하며 `data-table-actions` 작업 셀은 제외한다. 표 밖의 취소된 내용은 `data-cancelled-content={true}`를 사용한다. 서버의 최종 `CANCELLED` 또는 취소 시각만 근거로 사용하고 취소 결재 대기·반려·철회·개정 대체(`SUPERSEDED`)를 취소 완료로 취급하지 않는다. 원본 발행·인쇄 snapshot은 변경하지 않는다.
